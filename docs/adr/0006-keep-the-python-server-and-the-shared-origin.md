# Keep the Python server with kept-open connections, and accept the shared origin

Measured on the mini PC, a Splunk page takes 4 to 6 seconds whether or not it passes through the observer, so the proxy is not what makes pages slow. What the first server did cost was connections: it answered HTTP/1.0 and closed each one, so a page opened 55 to 85 TLS connections, and the TLS handshake ran in the accept loop. The server now speaks HTTP/1.1 with keep-alive, reuses one router connection per browser connection, sends length-less replies in chunks, compresses its own pages and JSON, and performs each handshake in the connection's thread. Putting HAProxy in front for HTTP/2 was considered and not done: it would need a second place that checks the observer login, and the six-connection limit of HTTP/1.1 did not show as queueing in measurements with eight live views.

A browser that does not trust the observer's self-signed certificate keeps no cache, and every Splunk page then downloads 3 to 4 MB again. The certificate must be trusted on the owner's Mac (ADR 0002); the wall says so when it sees Splunk's files being downloaded again.

Splunk Web is served on the observer's own origin (ADR 0001) so that it can be framed and so that the owner's page can read and act in the live view (ADR 0004). The cost is that script running inside any proxied Splunk page can call the observer's API with the owner's session, including approving a pending change or signing a view in as `lab_operator`. This cannot be closed while the page needs access to the frame. It is accepted for a single-owner lab on these conditions: only apps the owner trusts are installed in the lab, the observer is reachable only on the private LAN behind its login, and `lab_operator` exists only when the owner created it. Revisit this before the observer is used with untrusted apps or by more than one person.

A reading sent to a model holds only text that is visible on the screen, taken by walking the page's visible text, not its whole document. Splunk keeps hidden banners, menus and dialogs in the page, and reading those reported things the owner could not see. Raw events are still left out by the event viewer's markup, which does not cover a table or chart that an app fills with event text; a reading of such a page must be treated as able to contain event values.
