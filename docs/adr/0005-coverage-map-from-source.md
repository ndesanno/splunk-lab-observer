# Build each app's coverage map from its source at the installed version

The owner needs to know which features and screens of each lab app have been tested, and in which cases, before trusting a release. A hand-kept checklist drifts from the app; the lab's installed app list only names views. So the observer reads the inventory from the app's own source with `git show` and `git ls-tree` at a chosen ref, without touching the checkout: views and their labels (and whether the app menu lists them), SimpleXML panel titles, saved searches (scheduled, alerting, disabled by default), search commands, REST handlers, modular inputs, and KV store collections. For pages drawn by React, `coverage-sources.json` maps a UI source folder to the view it renders into, and each `<Heading>` text becomes a page section and each `<Button label>` an action. Every item carries the file and line it came from.

The ref is the source of the version actually installed. The observer counts the installed version and build across components and takes, in order: a tag (`v<version>-build.<build>`, `v<version>`) whose `app.conf` has that version and build; a local branch whose `app.conf` has it (an untagged release candidate); a tag with the version alone; and otherwise the default branch, saying so. Each component's installed version is shown next to the source version, marked as matching or not, together with the default branch's version and any uncommitted changes in the app folder. Inventories are cached per commit.

Coverage marks are rows in the observer's store: app, item, case (normal, empty, incorrect, permission, error, recovery), status, verdict, run, step numbers, note, author and time. The latest mark for an item and case wins, and older marks are kept. A case counts as tested only with a pass or fail verdict and evidence steps; otherwise it is stored as unverified. Claude marks cases with `record_coverage` from a run, with the step numbers that show the result. Claude Code in the terminal uses `observer.terminal coverage`. The owner can mark a case n/a, unverified or untested from the Coverage tab, but pass and fail come only from runs with evidence. Before a walkthrough, `propose_walkthrough` takes the app ids under test, and its plan card shows their installed and source versions, so the owner sees any mismatch before agreeing.
